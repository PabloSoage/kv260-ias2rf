# Symbol libraries

*Updated: 23 September 2026 (clock parts added the same day)*

A symbol whose pins are all `unspecified` makes ERC blind. That is exactly what produced the 48
uninterpretable `pin_to_pin` conflicts in the Rev01 work
([AUDIT_Rev01.md](AUDIT_Rev01.md) §2.2), and it is why this work exists: **every pin the design
uses has to carry a real electrical type**, or the verification story is theatre.

## 1. KiCad official libraries — used as-is

Not rebuilt. They ship with KiCad 10, are maintained, and copying them into a project library would
only create a second version to drift.

| Part | Library | Notes |
|---|---|---|
| **XC7A50T-FTG256** | `FPGA_Xilinx_Artix7` | The front-end FPGA. 256 pins, 4 units, 188 bidirectional + 68 `power_in`. Exactly the package AERIS-10 uses |
| ~~AD9708AR~~ | `Video` | Radar DAC. Replaced on 24 Sep by a project symbol from the datasheet: the stock one omits the NC pins and forced crossings. It stays the second source |
| **ADF4351** | `RF` | SDR synthesiser for the front-end board |

That the hardest symbol in the design — a 256-ball BGA — was already available and correctly typed
was the single biggest saving in this phase.

## 3. Where the data comes from

analog.com will not serve its PDFs to this machine — repeated 60 s timeouts, and the usual mirrors
return 403 and 410. Two other sources filled the gap.

### 3.1 Manufacturer datasheets

| Symbol | Datasheet | Table used | Obtained from |
|---|---|---|---|
| `AD9484BCPZ-500` | `AD9484.pdf` Rev. A | Table 7 | AERIS-10 component folder |
| `AD8352ACPZ` | `ad8352.pdf` Rev. C | Table 4 | AERIS-10 component folder |
| `M3SWA2-34DR` | `M3SWA2-34DR+.pdf` | Pad Description | AERIS-10 component folder |
| `LTC5552` | `LTC5552f.pdf` | Pin Configuration, Pin Functions | AERIS-10 component folder |
| `AD9523BCPZ` | `AD9523.pdf` Rev. D | Figure 2, Table 19 | Internet Archive |
| `AD9253BCPZ-125` | `AD9253.pdf` Rev. D | Figure 9, Table 8 | Internet Archive |
| `AD9767ASTZ` | `AD9763_9765_9767.pdf` Rev. G | Figure 5, Table 6 | Internet Archive |
| `ADCLK944BCPZ` | `ADCLK944.pdf` Rev. 0 | Figure 2, Table 6 | Internet Archive |
| `ADCLK948BCPZ` | `ADCLK948.pdf` Rev. B | Figure 2, Table 7 | Internet Archive |
| `Si549_PinoutC` | `Si549.pdf` Revision H (Skyworks) | Pin Assignments, Ordering Guide | Internet Archive |

**The Internet Archive route** is `_work/fetch_datasheets.py`. The Wayback Machine keeps copies of
analog.com's own URLs, and with the `id_` suffix it returns the archived bytes unmodified, so the
file is what analog.com served on the snapshot date. Two traps, both handled by the script:

- **Downloads on this machine are cut at exactly 1 MiB, without an error.** A larger datasheet
  arrives truncated but still starts with `%PDF` and half-renders. So files are fetched in HTTP Range
  chunks, and completeness is checked at the **end**: a whole PDF ends in `%%EOF`.
- **The AD9767 has no datasheet of its own.** It is published jointly as `AD9763_9765_9767.pdf`,
  and the Archive has no copy of any `AD9767.pdf` URL.

The script prints the snapshot, size and SHA-256 of each file. The PDFs themselves are Analog
Devices' copyright and are not in the repository (`_work/datasheets/` is git-ignored).

**Every table was read from the rendered page, not from extracted text.** Text extraction loses
overbars (so `REFA` and `REFA`-bar come out identical) and shuffles table columns. That's a real
risk on the AD9523, where 14 of its output pairs differ only by an overbar.

### 3.2 The AERIS-10 Eagle library, for the remaining two

Eagle records a direction per pin, which maps cleanly onto what KiCad needs:

```
in  -> input     out -> output    io  -> bidirectional    pwr -> power_in
sup -> power_out pas -> passive   oc  -> open_collector   hiz -> tri_state
nc  -> no_connect
```

Those boards were fabricated and measured, so a wrong pinout would have shown up as a dead board.
Good evidence, but **second-hand**, and every symbol carries a `SymbolSource` property saying which
route it came by.

## 4. Every datasheet table checked against a second source

A pin table typed by hand can be wrong in ways that stay invisible until the board is built: two
pins swapped, a complement on the wrong side of a pair, a supply read as a signal. The defence is
an independent second source, and `_work/crosscheck_pinouts.py` checks every datasheet symbol
against one where it exists: the AERIS-10 Eagle library, the EasyEDA pin names collected in
`_work/pinouts.txt` during the Rev01 work, or a pin-compatible part in KiCad's own libraries (the
Si549 in pinout code C against KiCad's Si570).

**The ADCLK948 has no second source** — it is in none of the three. The script lists it as such
rather than skipping it. Its only check is internal: the datasheet's pin drawing (Figure 2) and pin
table (Table 7) agree. That is why [CLOCK_SPEC.md](CLOCK_SPEC.md) §5 puts its pin numbers first on
the review list.

**Symbols drawn on a sheet get a hand-arranged pin layout** (`SYMBOL_LAYOUT` in
`_work/make_symbols.py`): the ADCLK948, the Si549, the AD9484 and the AD8352 so far. Only the
positions change. Pin numbers, names and types still come from the datasheet table, and the script
aborts if a layout omits or repeats a pin. The AD8352's left side reads VIP, RGN, RGP, RDP, RDN, VIN
so that each external part sits straight across its two pins
([ADC_RADAR_SPEC.md](ADC_RADAR_SPEC.md) §4).

```
symbol           2nd source  pins  agree  result
AD9484BCPZ-500   eagle        57     56  AGREE
AD8352ACPZ       eagle        17     16  AGREE
AD9523BCPZ       eagle        73     69  AGREE, 3 settled
M3SWA2-34DR      eagle        17     16  AGREE
LTC5552          eagle        13     11  AGREE, 2 settled
AD9253BCPZ-125   easyeda      49     43  AGREE, 5 settled
AD9767ASTZ       easyeda      48     48  AGREE
ADCLK944BCPZ     easyeda      17     16  AGREE
Si549_PinoutC    kicad         8      7  AGREE, 1 settled
ADCLK948BCPZ     -            33      -  NO SECOND SOURCE
No conflicts.
```

("agree" excludes the exposed pad, which each source names differently.)

Eleven disagreements were looked up and **settled against the datasheet**. They stay in the script's
output with the reason, rather than being normalised away:

| Symbol | Pad | Ours | Second source | Verdict |
|---|---|---|---|---|
| AD9523 | 55 | `STATUS1/SP1` | `STATUS1/SPI` | Eagle typo — SP1 is I²C address bit 1 |
| AD9523 | 69 | `NC` | `VDD1.8_PLL2` | Eagle predates Rev. D, which calls it NC but allows 1.8 V "on existing designs". Typed `passive` so either passes ERC |
| AD9523 | 72 | `PLL1_OUT` | `~PLL_OUT` | Eagle wrong twice: no overbar, and it is PLL**1** |
| LTC5552 | 3 | `IF-` | `IF` | Eagle lost the superscript minus |
| LTC5552 | EP | pad 13 | — | Eagle has no exposed pad; the datasheet does |
| AD9253 | 37, 38, 47, 48 | `VIN±B/C` | `VNI±B/C` | EasyEDA typo |
| AD9253 | 40 | `RBIAS` | `RBAIS` | EasyEDA typo |
| Si549 | 6 | `VDD` | `Vcc` | Naming only: KiCad's Si570 calls the supply Vcc |

**Every one of the disagreements was an error or a naming difference in the second source, not in the transcription.** That's the
result that makes the transcriptions trustworthy.

## 5. Errors this work found and fixed

### 5.1 Exposed pads were numbered to match the datasheet, not the footprint

The datasheets call the exposed paddle **pin 0**. KiCad's stock LFCSP/QFN footprints number it
**N+1** (`QFN-56-1EP_8x8mm…` has pads 1–57). A symbol pin has to match a footprint pad, or
`Update PCB from Schematic` leaves the paddle unconnected. On the AD9484 that pad is the ADC's
**only analogue ground**.

The first build of `AD9484BCPZ-500` used "0". Every symbol now numbers the paddle N+1: 57 on the
AD9484, 49 on the AD9253, 73 on the AD9523, 17 on the others. `make_symbols.py` refuses to write
the library if a datasheet symbol's pads don't run 1…N without gaps.

### 5.2 The M3SWA2 was missing its paddle

Found by the cross-check: the Eagle part had 17 pads and ours 16. The datasheet's Pad Description
says *"GND — 2, 4, 7, 9, 11, 14, 16 **& Paddle**"*, and the package is *"DQ3005, exposed paddle"*.
A 30 GHz switch with a floating main ground would not have worked. **Eagle was right**; the symbol
now has pad 17.

The same review renamed the RF ports to the datasheet's `RFOUT1`/`RFOUT2`, and retyped the three NC
pins as `passive`. They are *"not used internally, connected to ground on test board"*, so
grounding them is the recommended practice and must not raise an ERC error.

### 5.3 An erratum in the LTC5552 datasheet

Its Pin Functions section lists pin 3 twice: in *"GND (Pins 1, 3, 4, 6, 8, 10, 12…)"* and in
*"IF+, IF− (Pins 2, 3)"*. The Pin Configuration drawing shows pin 3 as IF−, and a differential IF
needs it, so the GND list is the error. The symbol keeps IF− on pin 3 and the code says why, so
that nobody "corrects" it back and grounds one side of the IF port.

### 5.4 B-03 had been closed wrongly

Retyping the `M3SWA2-34DR` from its datasheet showed that **blocker B-03 had been closed wrongly**.
It had been closed on a web search snippet reporting *"supply voltage requirement is 3.3V ~ 3.6V"*,
and the charge-pump inverter had been struck from the power tree on that basis. The datasheet
requires **VDD +3.3 V *and* VEE −3.3 V**; what is positive is the *control logic*. The rail is back;
see [BLOCKERS_AND_RISKS.md](BLOCKERS_AND_RISKS.md) B-03.

### 5.5 The AD9253's DRVDD is 1.8 V

Not a symbol error, but found while reading the same table: the power budget had DRVDD on 3.3 V,
above the part's 2.0 V absolute maximum. See [POWER_AND_STACKUP.md](POWER_AND_STACKUP.md) §1.2.

## 7. Validation performed

By KiCad, not by inspection:

```
kicad-cli sym upgrade      parses the library without error
kicad-cli sym export svg   renders all 17 symbols
kicad-cli sch erc          project ERC unchanged after rebuilding the library
```

Plus, in `_work/make_symbols.py`, duplicate-pad detection and pad-sequence completeness. And the
second-source comparison of §4, in `_work/crosscheck_pinouts.py`.
