# Symbol libraries — phase 2

*21 September 2026*

A symbol whose pins are all `unspecified` makes ERC blind. That is precisely what produced the 48
uninterpretable `pin_to_pin` conflicts in the Rev01 work
([AUDIT_Rev01.md](AUDIT_Rev01.md) §2.2), and it is why this step exists: **every pin the design
uses has to carry a real electrical type**, or the whole verification story collapses.

## 1. Where each symbol comes from

### 1.1 KiCad official libraries — verified, maintained, preferred

These are not rebuilt. They ship with KiCad 10, are community-maintained, and duplicating them
would only create a second copy to drift out of date.

| Part | Library | Notes |
|---|---|---|
| **XC7A50T-FTG256** | `FPGA_Xilinx_Artix7` | The front-end FPGA. 256 pins, 4 units, 188 bidirectional + 68 `power_in`. Exactly the package AERIS-10 uses |
| **AD9708AR** | `Video` | Radar DAC. Exact part-number match |
| **ADF4351** | `RF` | SDR synthesiser for the front-end board |

That the hardest symbol in the design — a 256-ball BGA — was already available and correctly typed
is the single biggest saving in this phase.

## 2. `[E]` Provenance, and how far to trust it

**The pin tables are not from the manufacturer datasheets.** analog.com would not serve its PDFs
from this machine — repeated 60 s timeouts, and the mirrors return 403 and 410. Rather than invent
pinouts, which is the one thing the working rules forbid outright, the tables were taken from the
**Eagle library of the AERIS-10 project**.

That is decent evidence. Those boards were fabricated, brought up and measured; a wrong pinout
would have shown up as a dead board. But it is **second-hand**, and every symbol carries a
`SymbolSource` property saying so.

**Where the source itself is weak, the symbol is weak in the same way.** Three of the seven come
out entirely or almost entirely `passive`:

- `M3SWA2-34DR` — 17 pins, all passive
- `AD9523BCPZ` — 73 pins, all passive
- `LTC5552` — 11 of 12 passive

Those Eagle symbols were drawn without typing their pins, so there is nothing to convert. **They
give ERC no more than an untyped symbol would.** They are usable as placeholders but must be
retyped from the datasheet before they earn any trust.

The four that did come through with real types — `AD9484BCPZ-500`, `ADAR1000ACCZN`, `ADF4382A`,
`AD8352ACPZ` — are genuinely useful to ERC today.

## 3. What has to happen before fabrication

| Symbol | Action |
|---|---|
| `AD9484BCPZ-500`, `ADAR1000ACCZN`, `ADF4382A`, `AD8352ACPZ` | Spot-check the pin table against the datasheet. The types are plausible and complete |
| `M3SWA2-34DR`, `AD9523BCPZ`, `LTC5552` | **Retype from the datasheet.** As they stand they defeat ERC |
| AD9253, AD9767 | Not yet built. `_work/pinouts.txt` holds EasyEDA pin names for both, but with `Dir = ?` throughout — names only, no types |

`_work/make_symbols.py` takes a pin table and emits a correct symbol, so once a datasheet is in
hand each of these is a short job rather than a drawing exercise.

## 4. Validation performed

Not by inspection — by KiCad itself:

```
kicad-cli sym upgrade      parses the library without error
kicad-cli sym export svg   renders AD9484BCPZ-500 (233 KB SVG)
kicad-cli sch erc          project ERC unchanged after registering the library
```
